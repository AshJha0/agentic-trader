Who this is for and how to use it

This page is a map of the project for three readers: students who want to see how an agentic AI system and a quant backtest fit together, researchers who want to check how results were tested, and desk engineers who want the code paths behind each control. Work through the two tracks in order, or jump to the cookbook and guide maps. Each step is a short summary with links into LEARN.md, COOKBOOK.md and the source; the linked text is the authority.

Evidence classes used in the repository docs (docs/learn/ai_learning_path.md): code (what the source does), offline test, synthetic fixture (numbers that say nothing about markets), arithmetic, measured (a real run, with its file), planning estimate. Every number on this page is copied from a named repository file.

How AI works here

1. LLM basics, as used here

The language model is Claude, called through agentic_trader/llm.py, or a small local model. It is off by default (llm_provider: "offline"), and every published backtest number except one small experiment comes from the rules, not from a model (docs/ai/ai.md, the short version). When it is on, it is handed facts the code already fetched and asked for judgement over them.

Read: LLMs · Local models · The language model · agentic_trader/llm.py · agentic_trader/local_llm.py

2. Agents and roles

An agent is a Python class with one job: analysts (technical, fundamentals or macro-rates, news, sentiment, alpha) write structured reports, bull and bear researchers debate them, the trader sizes around a strategic weight, a three-view risk team argues the size and the portfolio manager decides inside hard limits. Every agent gathers facts with tools, applies transparent rules, and only then may ask a model to reason over the same facts.

Read: Why a desk of specialist agents? · The analyst team · Debate as a decision mechanism · The agents on the desk · Agents and the harness · agentic_trader/graph.py

3. Tools, the policy gateway and MCP

Data is reached only through catalogued tools. Each call passes a policy gate that allows, denies or queues it for approval by explicit rule, and leaves SHA-256 evidence. The same tools are exposed over MCP and the HTTP API, under the same policy.

Read: Tools as the only way to reach data · Policy: who may do what, explained by rule · MCP, the API and observability · Tools and MCP · agentic_trader/agentic/policy.py

4. Retrieval, point in time

Retrieval runs over the desk's own runbooks and policies with a dependency-free hashed TF-IDF index; there is no embedding model. Research retrieval sits behind a gate: it is measured before an analyst may use it, and documents dated after the decision date are not visible.

Read: Retrieval over the desk's own rules · Measuring retrieval before an analyst may use it · RAG · Retrieval (RAG)

5. Guardrails and the boundary

The design rule: the model may interpret, the code decides what is allowed. Data is fetched by code, numbers are computed by code, and limits are enforced by code after the model has spoken. Model output must pass a structured contract gate, and the critic can only lower confidence, never raise it.

Read: Where the LLM sits, and where it does not · Structured outputs and the contract gate · The critic can only lower confidence · Guardrails · Hard limits after the model

6. Prompt injection red team

Untrusted text (news, filings) is contained before it reaches a prompt, and a red-team suite tries to push instructions through it. Since v0.17 the red team has a control arm, so a pass rate is compared with what an unprotected path would do; the numbers cover the attacks in the suite, not every attack.

Read: Red-teaming the fence, and what the numbers do and do not cover · A red team needs a control arm · docs/threat-model/threat-model.md

7. How the model is evaluated

The LLM study was pre-registered: each cell is a trial, the model is scored by information coefficient (IC) against the rules on the same dates, and a row is admissible only with its lineage. The v16 study was stopped before the first pass completed, so no pre-registered finding exists. The 2026-11-14 re-score of the stored rows gives IC minus rules for local_analysts of -0.030 [-0.140, +0.089], descriptive only; 404 of 1,200 analyst outputs in that cell came from the model (docs/evaluation/v16_prereg_status_2026-11-12.md).

Read: Asking a small model where it helps, and checking it first (v0.16) · Every study cell is a trial, and what a decision costs (v0.16) · Honest AI evaluation · v16 status · 2026-11-14 re-score · model card: LLM roles

How quant works here

1. Returns and excess returns

Sharpe is computed on returns in excess of the credited 3-month bill, and idle cash earns the cash rate. Worked example (docs/quant/quant.md, invented numbers, not a result): with w = 0.60, a 1% price rise and a 4% cash rate, the bar return is 0.60 x 1% + 0.40 x 4% / 252 = 0.6063%.

Read: One backtest, step by step · Constant units, idle cash and the fair comparison

2. Sharpe and its noise

A Sharpe ratio is an estimate with an error bar, and the best of N tries is biased upward. The repo reports bootstrap intervals, the probabilistic Sharpe ratio and the minimum track record; a Sharpe near 1 needs years of data to tell from luck (docs/quant/quant.md section 9).

Read: Is a Sharpe ratio real? Selection and deflation · Statistics: is the result real?

3. Volatility targeting and the fair control

Vol targeting holds less when recent volatility is high and more when it is low, with no view on direction. A desk that sizes by volatility inherits its benefit, so the fair benchmark is the vol-targeted holding. Example (LEARN.md section 37, v0.11): holdout Sharpe 0.91 desk, 0.86 buy and hold, 0.99 control; desk minus control -0.08 [-0.46, +0.30].

Read: The control that is hard to beat · Baselines and the fair control

4. Drawdown and Calmar

Maximum drawdown is the worst fall from a peak; Calmar divides return by it. Example (docs/evaluation/evaluation.md summary): core holdout mean maximum drawdown 13.19% for the desk, 31.50% buy and hold, 18.92% vol-target. Most of the gain over buy and hold is volatility scaling.

Read: evaluation summary · Reading the results honestly

5. Backtest hygiene: point in time and execution lag

Every input must be what was known on the decision date (filings by acceptance time, macro data by vintage), and a leak canary checks that shocking data after T leaves every output before T byte-identical. Execution lag tests deciding on a close not yet seen: registered trials at lag 0, lag 1 and next open, run 2026-11-13, show no trial beating the control at any timing, all p > 0.16 (LEARN.md section 61).

Read: Point in time is a property of the source · Purged cross-validation and the leak canary · Execution lag: deciding on a close you have not seen yet · exec-lag results

6. Costs

Costs are charged inside the backtest, on every baseline through the same engine. Example (docs/quant/quant.md): 2 bp per unit traded on a move from flat to 0.60 costs 0.00012 of equity, turning a 0.606% bar into about 0.594%.

Read: Execution costs belong in the backtest, not in a footnote · The backtester

7. Bootstraps: cross-instrument, cluster, time-block

A cross-instrument bootstrap resamples instruments; a cluster bootstrap resamples asset-class groups, because ten technology stocks are not ten independent tests; a time-block bootstrap resamples blocks of days and keeps autocorrelation. Review C8 found the daily returns were not passed into the slices, so the core and extended rows fell back to resampling instruments; since 2026-11-14 the time-block interval is primary for Sharpe on every slice, and drawdown and Calmar stay cross-instrument (docs/evaluation/evaluation.md summary).

Read: evaluation summary · Power across instruments, and the variance of a judgement

8. Multiple testing

Benjamini-Hochberg controls the false discovery rate across the rows of a table and across gates. Every variant ever judged is registered in evaluation.TRIALS (26 entries at v0.8), and the deflated Sharpe compares a result with the best expected from that many unskilled trials; the count is still a lower bound (LEARN.md section 25).

Read: Many gates are one family: Benjamini-Hochberg across them · Effective trials: hidden ones and correlated ones · One statistic, every trial, every row

9. FX accounting in USD

Notionals are in the account currency, USD by default: a USD/JPY order for 50,000 USD is 50,000 USD, and a EUR/JPY order needs the EUR/USD rate or is refused (LEARN.md section 21). Carry is booked from point-in-time rate differentials.

Read: Execution: from a weight to fills · Equity vs FX · Carry as a return stream

agentic-trader

An agentic AI trading desk for equities and FX. Specialist agents (technical, fundamentals or macro-rates, news, sentiment, alpha) write structured reports; bull and bear researchers debate them; a trader sizes the position around a strategic weight; a three-view risk team argues the size; a portfolio manager decides inside hard limits. Around the desk sits an enterprise-style harness: every data access is a catalogued, policy-gated tool call that leaves SHA-256 evidence, plans are validated before they run, a critic challenges the result, and the report is audited so every number and evidence id traces back. Below it, a C++17 quant core, an alpha library, execution algorithms and portfolio construction. Python · C++17 · pybind11 · MCP · FastAPI · Claude (Anthropic SDK) · FRED · walk-forward backtesting.

The model writes the reasoning; the numbers, the limits and the audit come from deterministic code. That boundary is enforced, not described. Every tool call is policy-checked and leaves a digest before an agent sees the result; findings whose evidence ids do not resolve are dropped; the critic may only lower confidence; the narrative is audited afterwards and every untraceable figure or id is attached as a warning — the adversarial suite feeds a fabricated "350 bps / 88% / CALC-badbadba" narrative, an injected headline that tries to close the untrusted block, a rogue plan with an order and a shell command, and a model that returns a 5.0 weight, and checks that each is contained. The performance figures above are from the rule-based desk; the LLM mode has not been evaluated. Out of sample the desk does not beat buy & hold on Sharpe per instrument — on the 15 names its rules were chosen on, and again on 45 names they never saw; it takes about half the drawdown on both. Adding the alpha library as an analyst measured as noise three times and stays off. With market impact on, the verdict holds at $100k and $10M and the desk loses 0.09 of Sharpe at $1B.

What's inside

Domain model

Frozen dataclasses for the whole vocabulary — Task, Plan, PlanStep, ToolDescriptor, ToolRequest/Result, Evidence (6 types), Finding, PolicyDecision, roles, capabilities and the 11-state task machine with its legal transitions. Nothing here imports an LLM SDK, MCP or a web framework.

Tool servers & executor

16 tools on 5 servers with schemas derived from Python signatures and annotations for read-only, risk level, capabilities and evidence type. The executor checks policy, coerces arguments, retries transient errors, times out, traces, and writes an evidence record for every call — including failures.

MCP server & client

The same catalogue as a real MCP server over stdio (official SDK 2.x), callable from any MCP client. The client side turns a remote server's tools into a local registry, so policy, evidence and tracing apply to remote tools unchanged — tested with a real subprocess round trip.

Policy engine & approvals

Ordered rules — deny list, required capabilities, read-only, argument guards (symbol universe, future dates, weight caps, lookback bounds), risk level — returning ALLOW / DENY / REQUIRE_APPROVAL with the rule named. Roles viewer, analyst, trader, risk, admin. Gateways: auto (dev), queued (a person decides via the API), deny.

Planner

A canonical plan per asset class, or a model-proposed one. The validator strips unknown tools, stages and arguments, pins every tool call to the task's symbol and date, refuses state-changing tools in plans, repairs stage order, and appends critic, validation and finalisation whenever a plan omits them. Unusable output falls back to the canonical plan.

Agent harness

CREATED → PLANNING → VALIDATING_PLAN → EXECUTING ⇄ AWAITING_APPROVAL → CRITIQUING → VALIDATING_EVIDENCE → FINALISING → COMPLETED. Parallel tool batches, pause and resume on approvals, cooperative cancellation, per-run tracer, and governance steps that a hand-built plan cannot skip.

The desk

Analysts (technical, fundamentals or FX macro, news, sentiment, optional alpha) that abstain without data; a bull/bear debate with a facilitator; a trader with strategic weight plus tilt and ATR stops; aggressive / neutral / conservative risk views; a portfolio manager with limits that run after any model output and a no-trade band.

Critic

Deterministic checks first: cited evidence must resolve; a model view must not diverge from its own rules by more than 0.6; strong contradictions need a balanced verdict; limits, stop sides and direction-vs-verdict must hold; single-evidence findings are capped. A model critique may then run and can only lower confidence.

Reporter with audits

Structured facts go to the model; the narrative comes back. A number audit checks every figure against the facts (rounding and percentage forms allowed, counts included) and an evidence-id audit checks every id; discrepancies are attached as warnings, not accepted.

RAG knowledge base

Eleven desk documents — risk limits, position sizing, stops, FX carry, execution, point-in-time data, evaluation protocol, incident runbook, alpha research, portfolio construction, agentic governance — chunked by heading, embedded with hashed TF-IDF, retrieved as DOCUMENT evidence and shown to the trader and PM.

Alpha library, time-series and cross-sectional

12-1 momentum, vol-adjusted momentum, short-term reversal, 52-week high, Donchian breakout, MACD, RSI, low-vol and FX carry — all in [-1, 1], point in time by construction. Per name: IC with t-stat, decay, hit rate, tercile spread, turnover. Across a universe (v0.5): daily z-scores or ranks within asset class, per-date IC with an overlap-aware t-statistic, top-minus-bottom quantile spreads, breadth.

Execution, in the simulator and in the backtest

TWAP, VWAP, participation-of-volume and Almgren-Chriss schedules; a simulator that builds intraday bars from the daily bar, charges half the spread and square-root impact, and reports implementation shortfall. v0.5 puts the same square-root model inside the backtester: a trade of |dw| costs |dw|^1.5 · Kt of equity, scaled by account size, charged to the desk and every baseline alike.

Portfolio construction with risk budgets

EWMA and Ledoit-Wolf shrunk covariance; equal, inverse-vol, risk parity, minimum variance and mean-variance weights with per-sleeve caps and a portfolio vol target; marginal and component risk, diversification ratio. v0.5 adds cross-asset risk budgets: allocate within each class, then risk parity with the budgets across classes from the full covariance, with budget vs realised share reported.

Operations

A SQLite task store that writes every run at each state transition and serves old records after a restart (in-flight runs are failed, never silently resumed); a dollar LLM budget next to the call budget; TLS on the API and a refusal to bind a public interface with the shipped development keys; ALFRED vintages so revised macro series enter the backtest as first published.

Backtest statistics

Block-bootstrap Sharpe confidence intervals, the probabilistic Sharpe ratio, the deflated Sharpe ratio for the number of variants tried, and the minimum track record length — applied to the desk's own 16-variant rule search.

HTTP API & observability

FastAPI gateway with API-key roles: 202-accepted tasks run in the background; reports as JSON or markdown; traces; evidence; cancel; an approvals queue for the risk role; the tool catalogue; health; Prometheus text metrics. Spans with parent ids and JSON-lines logs.

Adversarial suite and fuzzing

Injected headlines that try to close the untrusted block, rogue plans with orders and shell commands, unparsable planner output, a critic that tries to raise confidence, fabricated numbers and ids, unresolvable evidence, hostile arguments, role escalation, a plan without governance — each mapped to a control in the threat model. Plus hypothesis fuzzing of the Python ↔ C++ boundary on NaN, ±inf, empty and huge inputs, which found and fixed five backend divergences on its first run.

Offline by default

No API key, no network: deterministic rule-based agents on synthetic data run the whole harness, the API, the MCP server, the tests and the backtests out of the box. --data yahoo --llm anthropic switches to real data and Claude, with a hard call budget and anonymised prompts available.

Quick start

git clone https://github.com/AshJha0/agentic-trader && cd agentic-trader
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[all]"

# one task through the harness — offline, rule-based agents, ~30 ms
agentic-trader task EURUSD --date 2024-03-01 --position 0.2

# the catalogue, the API and the MCP server
agentic-trader tools
agentic-trader serve                      # docs at http://127.0.0.1:8000/docs
agentic-trader mcp

# research: alphas (per name and cross-sectional), execution, portfolio construction, statistics
agentic-trader alpha USDJPY --start 2021-01-04 --end 2024-03-28
agentic-trader xalpha AAPL,MSFT,NVDA,JPM,XOM --start 2021-01-04 --end 2024-03-28
agentic-trader execute AAPL --date 2024-03-01 --target 0.6 --current 0.1 --capital 5000000
agentic-trader portfolio AAPL,JPM,XOM,EURUSD,USDJPY --start 2023-01-02 --end 2023-12-29 --weighting risk_parity --class-budgets equity=0.6,fx=0.4
agentic-trader backtest NVDA --start 2024-01-02 --end 2024-03-28 --impact 1.0 --capital 1e9
agentic-trader stats returns.csv --trials 16

# the evaluation on real prices: 60 instruments, design / holdout / Q1 2024 / reserve
agentic-trader evaluate --data yahoo --universe all --periods design,holdout,q1_2024,reserve

# the suites (C++ core optional: scripts/build_cpp.sh or scripts\build_cpp.ps1)
pytest && ctest --test-dir build -C Release

# live: Claude + real prices (export ANTHROPIC_API_KEY=... or `ant auth login`)
agentic-trader task MSFT --llm anthropic --data yahoo --max-llm-calls 50 --llm-planner

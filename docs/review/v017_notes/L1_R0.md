## R0.1 Seeds at temperature 0 are replays (A1)

Plain idea: at temperature 0 the local model decodes greedily, so changing the seed changes
nothing. Two "seeds" were two copies of the same run, and the old report stacked them into one
series twice as long, which narrowed the interval by about 1/sqrt(2) for free.

What changed:
- `config.local_llm_temperature` (default 0.0). `LocalLLM` sends it as Ollama `temperature`
  (was hard-coded 0.0); negative values raise.
- `scripts/llm_study.py`: `check_seeds(seeds, temperature)` refuses `seeds > 1` unless
  `temperature > 0`; `run_study` calls it, `main` refuses `--seeds > 1` without `--temperature > 0`
  for `--live`/`--dry-run`. New `--temperature` (default 0). `--seeds` default 2 -> 1.
- `cell_metrics` scores each seed on its own (`per_seed`: Sharpe, diff, CI, p) on the dates all
  seeds share. The headline diff is the mean of per-seed diffs; its interval comes from
  `block_bootstrap_diff_seeds`, which draws one set of date blocks per resample and applies it to
  every seed (no concatenation, no block wrapping across seeds). `seed_replays` flags seeds whose
  period returns are identical.
- Formal statement: with seeds s = 1..S on common dates t = 1..n, diff = (1/S) sum_s [SR(a_s) -
  SR(b_s)]; resample index vector idx over t (circular blocks), recompute the same mean. If all
  a_s are equal, the statistic and every resample equal the one-seed values exactly.
- Worked example (test): two identical seeds give the same periods, diff, CI and p as one seed
  (`test_identical_seed_replays_do_not_narrow_the_interval`; on the old code `periods` doubled).

First pass (1 seed) is unaffected; its stored rows report the same numbers as before.

## R0.3 Each decision scored over its own horizon (B4)

Plain idea: analysts forecast 1-4 weeks, but the first-pass dates are ~3.6 months apart and the
old P&L held every weight to the next date. The report now scores each decision over 20 trading
bars, the top of the stated range.

- What rows store: `cell, seed, symbol, as_of, action, target_weight, source, sources, close,
  vt_weight, regime, seconds, calls`. No horizon and no forward price, so the forward close is
  read at report time from the same data provider (`--data`, default synthetic) by
  `horizon_returns`. Each decision's stored `close` must equal the provider close on `as_of`
  (relative 1e-6), else the decision is left out and listed: the report refuses to mix price
  sources silently.
- `horizon_metrics` (primary): per date, cross-sectional Spearman IC of `target_weight` against
  the 20-bar forward return (seed-averaged); mean IC with a 95% date bootstrap; hit rate (sign
  of weight = sign of return, over non-zero weights) with a 95% date bootstrap; IC minus the
  `rules` cell on paired dates with its interval. Dates resample i.i.d. because 20 bars is
  shorter than the gap between design dates (no overlap). Secondary: Sharpe of the per-date mean
  P&L at 252/20 periods per year. The old Sharpe table stays below it, labelled secondary.
- `--report` prints both; `--horizon N` changes the horizon.
- Tests (`tests/test_v17_r0_study.py`): forward return equals the hand-computed 20-bar return;
  a wrong stored close is rejected; a perfect-foresight cell gets IC > 0.95, hit rate 1.0 and an
  IC-minus-rules interval above 0; the report runs on rows written by `run_study` (no model).

To produce the corrected first-pass table once the chain finishes (no model; run in the clone
that holds the rows, with the same `--data` the run used):

    python scripts/llm_study.py --report --out results/p2/first_pass.jsonl --data <provider used by the run>

## R0.4 Schema ranges enforced, no clipping (A3)

- `contracts.py`: `minimum`/`maximum` on every bounded number (signals, scores, weights in
  [-1, 1]; confidence/conviction in [0, 1]; trader `horizon_days` in [1, 90]; stop/take
  `exclusiveMinimum: 0`). Enums were already present (facilitator `winner`, trader `action`).
- `contracts.violation(data, schema)` returns the first range/enum breach (enum compare ignores
  case, as the agents already lower/upper-case). `Agent._contract_problem` calls it, so an
  out-of-range reply is rejected whole and the rules apply. `StudyLLM._book` marks such a reply
  `unparseable`, so it counts in `contract_rejection_rate` and the admissibility share.
- `analysts.py` no longer clips signal/confidence (they are range-checked). The risk analyst
  still clips to `max_position` (a firm limit, not a range) and the PM guardrails are unchanged.
- The Anthropic structured-outputs endpoint does not take numeric bounds, so
  `contracts.api_schema` moves them into `description` for that path (`AnthropicLLM.build_request`);
  the contract check still enforces them. Ollama receives the bounded schema.
- `tests/test_agents.py::test_injected_model_cannot_breach_limits` now expects rejection (rules
  source) instead of clipping. New `tests/test_v17_r0_contracts.py`: signal 999 is rejected (on
  the old code it became +1.0 with source llm), every number in every schema is bounded, enum and
  range cases, no bounds in the Anthropic request, study books out-of-range as a rejection.
- Side effect: `Agent._contract_problem` source is in the prompt registry
  (`prompts.shared_prompt_code`), so the registry hash changes. Expected: a changed contract is a
  changed prompt set. P2 rows already written by the running chain were produced by the old code.

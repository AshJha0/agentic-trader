# Threat model

agentic-trader turns untrusted inputs (market data, news, social posts, macro series, model
output, plans, API requests, remote tools) into position sizes, evidence and reports. This
document lists what must be protected, where the trust boundaries are, and which control and
test handle each threat. Where a threat is only partly mitigated, it says so.

## Assets

| Asset | Why it matters |
|---|---|
| Final position size and direction | The only output that moves (simulated) capital |
| Evidence and audit trail | A report is only worth what its evidence proves; tampering makes every claim unverifiable |
| Backtest and evaluation integrity | Look-ahead, leakage or selective reporting makes every number meaningless |
| Numerical correctness of the quant core | Every agent's facts, every alpha, every metric depends on it |
| API credentials and spend | An `ANTHROPIC_API_KEY` or OAuth profile grants paid model access; an API key grants a role |
| Decision memory | Feeds lessons and a track record into later decisions |
| The knowledge base | Retrieved passages shape the trader's and risk team's prompts |

## Trust boundaries

1. **Data providers → tools → agents.** Prices, headlines, social posts, fundamentals and
   FRED series come from outside. Headlines and posts are free text written by third parties.
   Under the harness, every access is a tool call.
2. **Agents → LLM → agents.** Prompts leave the process; model replies (analyst views, plans,
   critiques, narratives) are untrusted text.
3. **Planner → harness.** A plan is a request, not an instruction; the validator and the policy
   engine decide what runs.
4. **Tool executor → policy → gateway.** The last point before a tool runs, and the only place
   a state change can be approved.
5. **Portfolio manager → critic → report.** Code overrides everything upstream; the critic can
   only lower confidence; the audits check the narrative.
6. **Python → C++.** Array data crosses into native code through pybind11.
7. **Client → HTTP API / MCP → harness.** Symbols, dates, positions, questions and approvals
   arrive over a socket or a pipe, with a role attached (over stdio, the role is the
   operator's choice for the session).
8. **Remote MCP servers → registry.** Tools discovered from another process carry their own
   descriptions and results.

## Threats, controls, tests

### Data and time

| # | Threat | Control | Test / evidence | Residual risk |
|---|---|---|---|---|
| T1 | **Look-ahead bias**: a provider returns bars after `as_of`, or a live decision "at the close" is made on a bar that is still trading | The provider contract, plus the graph re-clipping history to `<= as_of` regardless of provider; `YahooProvider` never serves or caches a bar dated today or later, where "today" is the calendar date in New York rather than the host's (a bar dated D is complete once it is D+1 in New York, which also lies after the 17:00 New York FX roll, so a host east of UTC+4 no longer sees the in-progress US bar as yesterday's); requests are clipped to that yesterday, coverage is recorded through the last complete bar, and the CLI's default date is New York's yesterday on the same rule | `test_propagate_offline`, `test_yahoo_never_serves_or_caches_todays_partial_bar`, `test_i_the_default_as_of_is_new_yorks_yesterday_whatever_the_host_clock_says` | None known for prices |
| T2 | **Leakage through fundamentals**: a current snapshot used for a past date | On real data the default source is SEC EDGAR, point in time by filing date (T37); `YahooProvider.fundamentals` returns nothing when `as_of` is more than 7 days before today; synthetic fundamentals publish with a 30-day lag | `test_synthetic_fundamentals_respect_publication_lag`, `test_fundamentals_are_point_in_time_and_first_print` | CSV users must supply point-in-time data themselves |
| T3 | **Leakage through news**: headlines after `as_of` | Every provider filters by date, and `NewsAnalyst` and `SentimentAnalyst` filter `published <= as_of` again; Yahoo news is not requested for dates it cannot serve | `test_synthetic_news_never_after_as_of`, `test_csv_news_filters_dates_and_blank_rows` | Timestamps are at day granularity: news published after the close on `as_of` is visible to that day's decision |
| T4 | **Leakage through memory**: using outcomes not yet known, or valuing an old call on a price the desk could not have seen | `resolve()` values an entry on the history handed to the desk at the current `as_of` (which ends at `as_of`), from the entry bar to the bar `horizon_days` trading days later, and only for entries recorded by the same provider and price basis (the entry-bar tolerance is the desk's own `max_data_staleness_days`, which the graph passes on every visit); an entry the series cannot value expires after twice its horizon instead of being booked, and a pre-v0.8 entry with no provider stamp is never valued — any named provider's visit past twice its horizon closes it out; `lessons()` and `track_record()` return only entries resolved on or before `as_of`, scoped to the provider | `test_memory_resolves_only_past`, `test_graph_records_provider_and_resolves_on_its_own_history`, `test_memory_horizon_is_counted_in_bars_whatever_the_weekday`, `test_graph_wires_the_staleness_setting_into_memory_so_a_gapped_entry_settles`, `test_legacy_entries_without_a_provider_stamp_are_closed_out_by_any_named_provider` | None known |
| T5 | **Execution-timing bias**: earning the return of the bar that produced the signal | The weight at bar *t* earns the return from *t* to *t + 1*; the last bar earns nothing. The FX spread is converted at the window's first price | `test_no_lookahead_timing` | None known |
| T6 | **Look-ahead in alphas or covariance** | Every alpha uses only bars up to *t* (rolling windows, lagged returns); covariance is estimated from trailing returns at each rebalance; the alpha report aligns signal at *t* with the return from *t* to *t + h* and its t-statistic uses the effective sample `n / h` of overlapping forward returns | `test_alpha_signals_are_bounded_point_in_time_and_complete`, `test_construct_end_to_end`, `test_portfolio_backtest_weighting_schemes`, `test_ic_tstat_uses_the_effective_sample_n_over_h_like_xalpha` | The design period was used to judge the alpha analyst, so it is in-sample for that choice |
| T7 | **Decisions on stale data**: a dead feed, a delisting or an outage leaves the last bar weeks old | `prepare` refuses when the last bar is more than `max_data_staleness_days` (7) before `as_of`; weekends and holidays pass | `test_stale_data_is_refused`, `test_weekend_as_of_uses_friday_close` | A feed that keeps publishing wrong but fresh prices is not detected |
| T8 | **Wrong instrument**: a mistyped pair silently becoming an equity ticker, or garbage symbols reaching a provider or an order ticket | `Instrument.parse` treats "/" and "=X" as FX intent and rejects invalid pairs; equity tickers must match a strict pattern; `argument_guard_rule` checks every `symbol` and every element of a `symbols` list against `agentic.symbol_universe`, and since v0.8 it runs *before* the approval outcome in `DEFAULT_RULES`, so it covers `execution.submit_order` as well as the read-only tools | `test_instrument_parsing_rejects_bad_symbols`, `test_policy_rules_in_order`, `test_argument_guards_run_before_the_approval_decision_for_state_changing_tools` | A valid but unintended ticker (a typo that is another real company) cannot be detected without a universe |
| T9 | **Macro look-ahead or stale macro** | `data/fred.py` shifts every observation by its publication lag and treats values older than their maximum age as unavailable; one resolver (`data/base.py fx_rates`) serves both the macro analyst and the credited carry, so on every bar the differential the desk is shown is the one the backtester credits, or both are absent. In FRED mode a stale, discontinued or unlisted leg gives no macro view and NaN carry; the illustrative static table is used only for synthetic data or `fx_macro_source="static"`, never as a fallback keyed to the wall-clock date. The on-disk FRED cache expires (`fred_cache_max_age_days`, default 1) and a download is validated before it is written | `test_fred_publication_lag`, `test_fred_staleness`, `test_fx_macro_modes`, `test_desk_macro_and_credited_carry_agree_on_every_bar_and_never_use_static`, `test_fred_disk_cache_expires_and_stale_cache_no_longer_yields_static_rates` | FRED serves the latest vintage: revised CPI can differ from first publication (T36). `RATE_SERIES` has no SEK series, so USDSEK has no macro view at any date on real data |
| T10 | **Messy input files**: unsorted rows, duplicate dates, blank or zero closes, highs below closes, time zones, two price bases in one file | `clean_ohlcv` normalises every provider's output (a non-finite close drops the bar, `+inf` open/high/low are repaired); `csv_provider.one_basis` puts Open/High/Low/Close on the adjusted basis when both `Close` and `Adj Close` are present, drops raw O/H/L (with a warning) when only `Adj Close` is, keeps a row with a blank `Adj Close` on the nearest row's factor, and rescales `Volume` by the split component of the factor only (a day-over-day jump above 5%), never by the dividend drift, so dollar volume and ADV stay as traded across a split and a dividend payer's volume is served as traded | `test_clean_ohlcv_repairs_messy_input`, `test_csv_lowercase_adj_close_unsorted`, `test_csv_close_and_adj_close_put_every_price_column_on_the_adjusted_basis`, `test_h_volume_is_rescaled_so_dollar_volume_stays_as_traded_across_a_split`, `test_fd_a_dividend_payer_without_a_split_keeps_its_volume_as_traded` | Split or dividend errors in user files are not detected; a special dividend above 5% is read as a split |
| T11 | **Corrupt or lost decision memory** from a crash mid-write, a hand edit, or two writers sharing one file | The log is append-only: one line per decision and one per resolution, each written with a single `write` and `fsync` under an in-process `RLock` and a file lock on the append (`msvcrt.locking` on Windows, `fcntl.flock` elsewhere), so threads in one process and separate `serve` processes sharing `results/memory.jsonl` never rewrite each other's records on any platform (the v0.7 temp-file-and-rename of the whole file is gone); unreadable lines are skipped with a warning and counted; legacy files load, and a repeated line for the same key collapses to the latest | `test_memory_survives_corrupt_lines_and_appends_under_a_lock`, `test_memory_log_survives_eight_threads_and_reloads_every_record`, `test_memory_instances_in_separate_processes_do_not_overwrite_each_other`, `test_memory_reads_legacy_lines_and_deduplicates_repeated_scans` | Skipped entries are lost to reflection. Entries recorded by pre-v0.8 files carry no provider and are only expired, by any named provider's visit; they never resolve |

### Models and prompts

| # | Threat | Control | Test / evidence | Residual risk |
|---|---|---|---|---|
| T12 | **Prompt injection via news, social text, retrieved passages, or text written from them** | Third-party text reaches the model only inside `<untrusted_data>` blocks; tag open/close attempts inside the text are neutralised; the fence also covers what is *derived* from that text: the analyst digest fences the summary and key points of analysts with untrusted inputs (news, sentiment), memory lessons enter the researcher, trader and PM prompts through `TradingState.lessons_block()`, fenced, and the debate turns, verdict, proposal and risk views downstream of an untrusted report enter later prompts through fenced blocks (`state.fenced`); under the harness every finding written from such text carries `Finding.untrusted` and the critic's and reporter's prompts render it, and a decision rationale downstream of it, inside one fence (`critic.findings_block`, `decision_untrusted`), prefixed with `FENCE_NOTE`; `FIRM_CONTEXT` says the fence covers text written from third-party material. Model output is clipped or rejected; firm limits run after the model; the critic flags a model view that diverges from the rule view by more than `critic_divergence` | `test_untrusted_block_cannot_be_closed_from_inside`, `test_headlines_reach_the_model_only_inside_the_block`, `test_injected_headline_stays_fenced_in_every_downstream_prompt_and_in_memory`, `test_model_written_text_derived_from_fenced_input_stays_fenced_one_hop_later`, `test_critic_and_reporter_prompts_fence_claims_written_from_third_party_text`, `test_injected_model_cannot_breach_limits`, `test_injected_headline_is_fenced_and_bounded`, `test_critic_flags_divergence_wrong_side_levels_and_limits` | **Partial.** Injected text can still bias a direction *within* the limits; the critic lowers confidence but does not veto. A model-written technical or fundamentals summary derives from numbers only and is not fenced; `FinalDecision` itself carries no untrusted flag (the critic recomputes it from the state) |
| T13 | **Malformed or hostile LLM output**: prose, broken JSON, missing keys, `null` or a string where a number belongs, `NaN`, `inf`, wrong-side stops, absurd horizons | `extract_json` accepts only a JSON object and rejects bare `NaN` / `Infinity`; `Agent.ask_json` rejects the *whole* reply (rules apply, `source = "rules"`) when a required numeric key is `null`, a string, a boolean or non-finite, or an optional one is present and not a finite number -- nothing is coerced to 0, so a `null` target weight no longer liquidates a position; finite values are then clipped to their ranges; `sane_levels` replaces wrong-side stops and targets; horizons are clipped to 1--90 trading days | `test_llm_garbage_falls_back_to_rules`, `test_trader_reply_with_an_invalid_number_is_rejected_not_zeroed`, `test_every_agent_rejects_a_present_but_invalid_numeric_field`, `test_extract_json_rejects_nan_and_infinity`, `test_injected_model_cannot_breach_limits`, `test_sane_levels` | A finite but absurd number is clipped to its range, not rejected |
| T14 | **Model refusal, timeout or API failure** mid-pipeline | A refusal and typed SDK errors return `None`, and the agent uses its rule-based result; requests time out after `llm_timeout_s`; the client's own retry loop (`llm_max_retries`, default 2; the SDK client is built with `max_retries=0`, so every attempt is observed) bills a timed-out attempt at a full `max_tokens` reply rather than at $0, waits the server's `retry-after` / `retry-after-ms` header on a 429 or 529 (up to 60 s) and otherwise a jittered `llm_retry_backoff_s` backoff, validated finite and non-negative at construction; an effort level outside `low|medium|high|xhigh|max` is refused at construction rather than silently sent as `high`; request parameters are shaped per model family (`request_shape`), so an older model id gets a plain request instead of failing every call | `test_anthropic_llm_request_shape_usage_and_failure_branches`, `test_request_shape_only_sends_parameters_the_model_family_accepts`, `test_every_timed_out_attempt_is_billed_even_when_a_retry_succeeds`, `test_retries_honour_the_servers_retry_after_header_and_validate_the_backoff`, `test_effort_outside_levels_is_rejected_at_construction`, `test_llm_garbage_falls_back_to_rules` | Degraded (rule-based) reasoning for that step, visible as `source = "rules"` |
| T15 | **Cost runaway** from many LLM calls | `max_llm_calls` and `max_llm_cost_usd` wrap any model in `BudgetedLLM` (a call count does not bound a bill: an Opus call is ~15 Haiku calls); `UsageTracker` records tokens and estimated cost per run (its reads take the same lock as its writes); before a call is dispatched its reservation is taken under the lock and calls in flight count against the cap. Under `llm_budget_mode: hard` (the default) the reservation is the most the call can cost — 8,000 input tokens plus a full `max_tokens` reply at list price, which is also what a timed-out attempt is billed at — so spend is bounded by the cap, parallel workers cannot each slip one call past it, and a cap that cannot afford one such call refuses that tier before any spend (`exhausted_for(deep)`); `estimate` reserves the input estimate plus `llm_reserve_output_tokens` (2,000) and is a documented soft cap; a served model id with no list price makes the budget exhausted (fail closed) and an unpriced configured id is refused at construction; abstaining analysts make no call; offline is the default | `test_budgeted_llm_caps_calls_and_falls_back`, `test_dollar_budget_caps_spend`, `test_dollar_budget_reserves_calls_in_flight_so_workers_cannot_overshoot`, `test_hard_budget_mode_bounds_spend_and_estimate_mode_is_a_documented_soft_cap`, `test_budget_exhausted_agrees_with_complete_on_the_tier_it_is_asked_about`, `test_dollar_budget_fails_closed_for_an_unpriced_served_model`, `test_usage_tracker_prices_by_serving_model`, `test_usage_tracker_reads_by_model_under_its_lock`, `test_budget_is_thread_safe` | The caps are per graph, not per account; the dollar figure uses list prices; the hard reservation is conservative, so a small cap admits fewer concurrent calls than its balance suggests, and a timed-out call is billed as if every attempt was served in full. Under `estimate` the overshoot is bounded by the calls in flight × (`max_tokens` − 2,000) × the output price. A custom `LLM` object without `estimate_cost` reserves nothing, so under a dollar cap it keeps the per-worker overshoot |
| T16 | **Sensitive prompt content**: symbols, positions, dates or a company fingerprint leaving the process | `llm_anonymize` replaces instruments, names and dates with placeholders before the call and maps them back after; prices are rebased so the last close is 100; the fact list is an allow-list -- only known scale-free keys (returns, ratios, rates, volatilities, indicator values, counts) pass, so TTM revenue, EPS, market capitalisation, the sector string and the cross-sectional peer list never reach an anonymised prompt and `pe_ratio x eps_ttm` cannot reproduce the real close | `test_anonymized_prompts_leak_no_name_date_or_price`, `test_anonymizer_fx_pair_and_codes`, `test_anonymised_prompts_drop_absolute_scale_fundamentals`, `test_anonymizer_facts_is_an_allow_list`, `test_anonymised_xalpha_prompt_names_no_peer` | **Partial.** The shape of the return series itself, distinctive statistics (a -0.1% policy rate) and company names in real headlines can still identify the instrument and the date; no de-anonymisation probe has been run against a model, so the residual leakage is asserted, not measured. Anonymisation is off by default |
| T17 | **A rogue plan**: the model asks for tools that do not exist, another symbol, date or position, a state change, a duplicated step, or a plan that would load an unbounded amount of data, or drops the governance steps | `validate_plan` strips unknown tools, pins the task's symbol and date, drops a model-written `current_weight` whenever the run's book holds the symbol (the book, not the model, is the source of the position), coerces arguments against the schema, repairs a string `symbols` to a list and drops a step whose `symbols` is any other shape, clips a `symbols` list to the universe and to `agentic.max_symbols_per_call` (dropping the step only when nothing is left), drops state-changing tools and duplicate `(tool, arguments)` steps, enforces a per-plan data budget (`agentic.max_plan_lookback_bars`, 200,000 symbol-days), and appends the critic, evidence validation and finalisation steps; every repair is a note, never a failed run; every tool step is then pre-checked against policy | `test_validate_plan_strips_repairs_pins_and_appends_governance`, `test_rogue_plan_is_repaired_not_executed`, `test_governance_cannot_be_skipped`, `test_validate_plan_drops_duplicate_tool_steps_and_keeps_the_budget`, `test_validate_plan_clips_symbol_lists_to_the_universe_instead_of_failing_the_run`, `test_validate_plan_repairs_a_string_symbols_argument_and_drops_other_shapes`, `test_a_book_position_above_the_cap_is_one_fact_for_the_planner_the_agents_and_the_tools`, `test_a_36k_evaluation_plan_is_rejected` | A plan that omits useful steps degrades quality, not safety. A model plan with `lookback_days` above 3660 or a `target_weight` above the cap still fails the harness pre-check rather than being clipped |
| T18 | **A critic or narrative that inflates confidence** | The model critique's multiplier is clipped to at most 1 and its concerns are appended, never removed; a malformed critique (`concerns: null`, a missing or non-numeric multiplier) is recorded as a failed `llm_critique_wellformed` check and ignored rather than crashing the run; the deterministic checks run regardless | `test_llm_critique_can_only_lower_confidence`, `test_critic_cannot_raise_confidence`, `test_critic_tolerates_malformed_model_critiques` | A model critique that is too lenient adds nothing; the deterministic checks are the floor |
| T19 | **A fabricated narrative**: numbers or evidence ids that are not in the facts | `number_audit` accepts only numbers that match a fact when the fact is rounded to the displayed precision (counts included); `evidence_audit` rejects unknown ids; failed audits are attached to the report | `test_number_and_evidence_audits`, `test_report_flags_fabricated_numbers_and_ids_from_a_model`, `test_fabricated_narrative_is_audited` | A narrative can omit facts; the audits check what is said, not what is left out |
| T20 | **Knowledge-base poisoning**: a hostile document steering the trader | The knowledge directory ships with the package and is loaded from disk, never the network; `knowledge.list_documents` shows what was loaded; the trader and risk prompts take at most three passages truncated to 400 characters, labelled as retrieved policy; the firm limits and the critic run after the model | `test_knowledge_base_retrieval`; code review of `policy_passages` | **Partial.** Passages are presented as firm policy to follow, so anyone who can write to the docs directory can bias a direction within the limits. Keep the directory read-only in deployment. The prompt-registry hash (T40) covers the retrieval code, not the documents' text, so an edited policy document does not change a result's recorded prompt bundle |

### Tools, policy and services

| # | Threat | Control | Test / evidence | Residual risk |
|---|---|---|---|---|
| T21 | **Approval bypass**: a state-changing tool runs without a human, or a person approves an order whose size or instrument was never checked | `DEFAULT_RULES` runs the deny list, the capability check and the argument guards *before* the approval outcome, so a state-changing request with a bad argument (an out-of-universe symbol, a non-finite quantity, a notional above `max_order_notional`) is `DENY(argument_guard)` and is never parked for approval; ## Out of scope

- Live trading, order routing and broker credentials: `execution.submit_order` records an
  order ticket (quantity in its unit, notional, currency, reference price, plan reference,
  intent against the book) as evidence and does nothing else.
- Market-abuse surveillance.
- Multi-tenant isolation: one harness serves one desk. The HTTP API authenticates by key but
  every key sees the same tasks.
- A distributed queue: `serve --processes N` runs several uvicorn processes over one task
  store, with per-record ownership and heartbeats so a live sibling's runs survive another
  process's restart, but work is not handed between processes and a cancel or approval must
  reach the process that owns the run.
